# Dolas 资产系统后续路线图

更新日期：2026-08-14

## 1. 当前结论

Dolas 的引擎级资产继续以 **C++ 代码作为权威结构定义**。XML 只是资产数据的序列化格式，不再承担 schema 定义，也不再通过 precompile 生成 C++ 头文件。

后续遵循以下边界：

- C++ 定义字段类型、默认值、稳定类型 ID、schema 版本、稳定字段 ID 和校验规则。
- `AssetManager` 负责读取、校验和缓存；运行时系统不直接解析 XML。
- 资产编辑器使用 C++ 与 ImGui 实现，并复用同一套反射和校验信息。
- Lua 通过引擎提供的资产绑定读取已加载资产，不单独实现 XML 解析器，也不复制一套资产结构。
- 只有在未来需要“Lua 可以定义无需 C++ 参与的新资产类型”时，才重新评估语言无关 IDL；仅让 Lua 读取资产不需要恢复 RSD。

## 2. 已完成的基线

当前版本已经具备：

- `AssetPath`：校验并规范化 `_engine/` 与 `_project/` 逻辑路径。
- `AssetDescription` 与 `AssetReflection<T>`：使用类型安全的成员指针描述字段，不再依赖 `offsetof` 和字段级 `void*` 写内存。
- 稳定契约：每种资产具有 `kTypeId`、`kFileSuffix` 和 `kSchemaVersion`，每个字段具有稳定数字 ID。
- `AssetRef<T>` 与 `RawAssetRef`：结构化资产引用保留目标 C++ 类型，原始文件引用也统一使用 `AssetPath`。
- 五种内建描述：Camera、Material、Mesh、Entity、Scene。
- 严格 XML 读取：检查根节点、类型、版本、未知/重复/必填字段、数值范围、枚举和引用后缀。
- `AssetManager::LoadAsset<T>()`：按规范路径缓存资产，加载器使用稳定字符串类型 ID 注册。
- 现有运行时代码和 content 资产已迁移；旧 RSD 元数据和生成头文件已移除。
- 当前 Debug 构建成功，CTest 157/157 通过，包含初始化引擎并渲染一帧的 Windows smoke test。

当前项目中不存在第一方 C# AssetEditor 或其他 C# 工具项目，因此没有需要额外删除的第一方 C# 代码。

## 3. 当前仍有的限制

- 反射目前主要是编译期结构，尚无供 ImGui/Lua 通用访问的运行时类型擦除视图。
- 只支持读取，没有通用 XML 写回、round-trip 和原子保存能力。
- schema 版本目前只能精确匹配，还没有旧版本迁移函数。
- `AssetRef<T>` 只验证路径格式和后缀，不验证目标文件是否存在，也没有依赖图和循环依赖诊断。
- `AssetLoadResult<T>` 返回缓存内对象指针；`AssetManager::Clear()` 后失效，不适合直接暴露给 Lua 长期持有。
- 缓存没有线程安全、异步加载、卸载策略、热重载和依赖失效传播。
- 资产身份目前等同于规范路径，移动或重命名文件会使引用失效。
- Camera、Mesh 等类型仍缺少跨字段语义校验，例如 `near_plane < far_plane`、顶点流长度一致、索引不越界等。
- 内建资产类型仍在 `AssetManager::Initialize()` 中手动注册，尚未集中检查重复类型 ID、后缀和版本。

## 4. 推荐实施顺序

### 阶段 A：补强正确性

优先级最高，完成后再建设编辑器或 Lua 接口。

1. 为全部字段类别补充测试：标量、Vector、枚举、数组、Map、Optional、`AssetRef<T>`、嵌套对象。
2. 覆盖全部错误分类：错误类型 ID、缺失/非法版本、未知字段、重复字段、必填字段缺失、数值越界、错误引用后缀。
3. 增加现有 `content/` 的批量加载测试，确保所有受支持资产都可读取。
4. 为各资产类型增加语义校验：
   - Camera：近平面为正、远平面大于近平面、方向向量有效。
   - Mesh：顶点属性步长和顶点数一致、索引有效、拓扑与索引匹配。
   - Scene：旋转与缩放有效、必需引用存在。
   - Material：Shader/Texture 引用存在并符合用途。
5. 将内建类型注册集中到 `AssetTypeRegistry`，启动时拒绝重复类型 ID、重复后缀或非法 schema。

验收标准：错误资产稳定失败并返回准确原因；仓库内所有合法资产都可由自动测试加载。

### 阶段 B：保存与版本迁移

1. 实现与读取器共用反射信息的 `AssetWriter`，保证稳定字段顺序和确定性输出。
2. 实现临时文件写入、校验后替换的原子保存，避免编辑器崩溃破坏资产。
3. 增加 round-trip 测试：`读取 → 写出 → 再读取` 后语义一致。
4. 建立显式迁移表，例如 `(type_id, from_version) -> migration`；逐版本迁移，不静默猜测旧格式。
5. 明确字段改名规则：字段数字 ID 保持不变，序列化名称变化必须提供迁移或旧名称别名。

验收标准：编辑器可以安全保存资产；旧版本资产要么确定性迁移，要么给出明确的不支持错误。

### 阶段 C：运行时反射与 C++/ImGui 编辑器

1. 在编译期 `AssetReflection<T>` 之上提供只读的运行时描述：类型 ID、版本、字段 ID、显示名、类型类别、范围、枚举项和访问回调。
2. 访问回调必须通过受控 visitor/getter/setter 完成，不向外暴露字段偏移或任意 `void*` 运算。
3. 实现通用 ImGui Inspector：标量、向量、枚举、数组、Map、Optional 和资产引用控件。
4. 实现 Dirty 状态、校验提示、撤销/重做、保存/另存为和外部文件修改检测。
5. 将 Inspector 接入现有 Content Browser；资产引用控件支持筛选兼容类型及拖放。

验收标准：新增一个普通 C++ 资产字段后，不需要为编辑器手写同类控件或单独维护 schema。

### 阶段 D：依赖、身份与运行时生命周期

1. 构建资产索引与依赖图，记录正向引用和反向引用。
2. 加载时诊断目标不存在、类型不匹配和循环依赖；编辑器移动文件时可以更新引用。
3. 决定是否引入稳定 `AssetId`/GUID：
   - 短期可继续使用规范路径作为身份。
   - 在支持资产重命名、跨目录移动或大型项目协作前，应引入与路径分离的稳定身份。
4. 用带 generation 或共享所有权的 `AssetHandle` 替代跨系统长期保存裸指针。
5. 增加缓存状态机、线程安全、异步加载、取消、引用计数/预算卸载。
6. 实现文件监控、热重载及依赖失效传播；失败时保留上一份有效资产。

验收标准：资产可安全重载和卸载；调用方不会持有悬空指针；依赖变化能够精确传播。

### 阶段 E：Lua 读取接口

Lua 接口依赖阶段 C 的运行时反射和阶段 D 的安全句柄，不应直接绑定当前缓存裸指针。

建议的脚本语义：

```lua
local result = Assets.load("dolas.camera", "_engine/camera/default.camera")
if not result.ok then
    error(result.error)
end

local camera = result.asset
print(camera.position.x)
```

具体要求：

1. Lua 使用稳定类型 ID 和 `AssetPath`；不使用 C++ `typeid`、类名或内存布局。
2. 首版只提供只读代理；修改资产仍由 C++/ImGui 编辑器负责。
3. 代理持有 `AssetHandle`，在 reload/unload 后能够检测 generation 变化或安全失效。
4. 统一绑定标量、Vector、枚举、数组、Map、Optional 和资产引用。
5. 加载错误以结构化结果返回 Lua，不依赖日志文本判断。
6. Lua 不直接打开或解析资产 XML，避免形成第二套默认值、校验和版本迁移逻辑。

如果未来只需要脚本私有配置，可单独提供 `ScriptDataAsset` 或 Lua table 数据文件；不要因此把所有引擎资产结构改成 Lua 定义。

验收标准：Lua 与 C++ 读取同一缓存对象，并观察到一致的默认值、枚举、引用和热重载结果。

### 阶段 F：导入与 Cook 流程

1. 区分源资产、编辑器资产描述和运行时 Cook 产物。
2. 为 Mesh、Texture、Shader 等建立 importer，记录 importer 版本、参数、输入哈希和依赖。
3. 以内容哈希缓存导入结果，只重建发生变化的资产及其下游。
4. 设计发布包中的只读虚拟文件系统和 mount，不让运行时依赖编辑器 XML。
5. 最终由运行时加载紧凑、版本明确、适合流式读取的 Cook 格式。

验收标准：修改源文件只触发必要的重新导入；发布版本无需携带源资产和编辑器专用信息。

## 5. 暂时不要做的事情

- 不恢复 RSD/precompile，只为减少几行 C++ 反射声明而增加第二权威源。
- 不让 Lua、编辑器和运行时各自实现一套 XML 读取器。
- 不把 C++ RTTI、对象地址、成员偏移或缓存裸指针暴露给 Lua。
- 不在尚无第二个 schema 版本时过度设计复杂迁移语言；先保留清晰的迁移接口。
- 不立即引入 GUID、数据库、异步流送等全部大型机制；按上述阶段由测试驱动演进。

## 6. 下一次继续时的第一项工作

从“阶段 A：补强正确性”开始：先为五种内建资产建立覆盖全部字段类型和错误分类的测试，并加入仓库 `content/` 批量加载测试。完成这些测试后，再抽取 `AssetTypeRegistry`；不要直接从 ImGui 或 Lua UI 开始。
