# Dolas Engine 代码重构方案

## 文档信息
- **创建日期**: 2026年3月10日
- **目标版本**: v1.0
- **文档状态**: 草案

---

## 1. 执行摘要

本文档识别了Dolas Engine代码库中存在的工程规范违规和最佳实践缺失，并提供系统化的重构方案。重构目标包括：
- 提高代码可读性和可维护性
- 增强系统健壮性和安全性
- 改善可扩展性和测试性
- 统一工程规范和代码风格

---

## 2. 发现的问题分类

### 2.1 命名规范违规

#### 2.1.1 拼写错误
- **严重程度**: 中等
- **位置**: `dolas_math.h:285`
- **问题**: `Pose`类成员变量 `m_postion` 拼写错误，应为 `m_position`
- **影响**: 影响API一致性，可能导致调用者困惑

#### 2.1.2 常量命名不一致
- **严重程度**: 低
- **位置**: `dolas_math.h:11-15`
- **问题**: `DOLAS_FLOAT_INFINITY` 和 `DOLAS_FLOAT_POSITIVE_INFINITY` 重复定义
- **建议**: 统一使用 `DOLAS_FLOAT_INFINITY` 表示正无穷

### 2.2 架构设计问题

#### 2.2.1 全局状态过度依赖
- **严重程度**: 高
- **位置**: 多处使用 `g_dolas_engine` 全局变量
- **示例**:
  ```cpp
  // dolas_rhi.cpp:27
  return g_dolas_engine.m_input_manager->MsgProc(hwnd, msg, wParam, lParam);
  
  // dolas_rhi.cpp:199
  Texture* scene_result_texture = g_dolas_engine.m_texture_manager->GetTextureByTextureID(...);
  ```
- **问题**: 
  - 造成组件间紧耦合
  - 难以进行单元测试（无法mock依赖）
  - 隐藏依赖关系，增加理解成本
  - 违背依赖注入原则

- **影响**: 
  - 代码难以复用
  - 测试需要设置复杂的全局状态
  - 无法并行运行多个Engine实例

#### 2.2.2 Manager类职责过重
- **严重程度**: 中等
- **位置**: 所有 `*Manager` 类
- **问题**:
  - 同时承担资源创建、缓存、生命周期管理
  - 部分Manager包含业务逻辑（如渲染管线配置）
  - 缺乏明确的接口抽象

### 2.3 内存管理问题

#### 2.3.1 原始指针使用
- **严重程度**: 高
- **位置**: 
  - `dolas_material_manager.h:39`: `std::unordered_map<MaterialID, Material*> m_materials`
  - `dolas_render_object_manager.cpp:113`: 手动内存管理注释
- **问题**:
  - 缺乏RAII保护
  - 容易出现内存泄漏
  - 异常安全性差

#### 2.3.2 COM资源管理混乱
- **严重程度**: 高
- **位置**: `dolas_rhi.cpp` 各处
- **问题**:
  - 混合使用裸指针和智能指针
  - `DOLAS_DELETE` 宏用于COM接口不安全
  - 析构函数手动调用 `Release()` 容易出错
  
- **示例**:
  ```cpp
  // 危险的宏用法
  DOLAS_DELETE(m_d3d_device); // 错误！应该使用 Release()
  ```

### 2.4 代码重复

#### 2.4.1 资源视图类重复模式
- **严重程度**: 中等
- **位置**: `dolas_rhi.cpp:35-124`
- **问题**: 
  `RenderTargetView`, `DepthStencilView`, `RasterizerState`, `BlendState`, `InputLayout` 等类的析构函数几乎完全相同

- **重复代码模式**:
  ```cpp
  ClassName::~ClassName()
  {
      if (m_d3d_resource)
      {
          m_d3d_resource->Release();
          m_d3d_resource = nullptr;
      }
  }
  ```

#### 2.4.2 状态初始化代码重复
- **严重程度**: 中等
- **位置**: `dolas_rhi.cpp:726-779`
- **问题**: 光栅化状态描述符初始化代码重复4次

### 2.5 错误处理不一致

#### 2.5.1 返回值类型不统一
- **严重程度**: 中等
- **位置**: `dolas_rhi.h`
- **问题**:
  - `Initialize()` 返回 `bool`
  - `Clear()` 返回 `void`
  - `CreateDepthStencilState()` 返回 `Bool`
  - 缺乏错误码体系

#### 2.5.2 宏使用混乱
- **严重程度**: 低
- **位置**: 多处
- **问题**:
  - `HR()` 宏用于D3D调用
  - `DOLAS_RETURN_*` 宏用于早期返回
  - 缺乏错误日志上下文

### 2.6 API设计问题

#### 2.6.1 暴露内部实现
- **严重程度**: 中等
- **位置**: `dolas_rhi.h:39-40`
- **问题**:
  ```cpp
  ID3D11Device* GetD3D11Device() const { return m_d3d_device; }
  ID3D11DeviceContext* GetD3D11DeviceContext() const { return m_d3d_immediate_context; }
  ```
- **影响**: 
  - 违背封装原则
  - 客户端代码可能直接操作D3D资源
  - 难以切换到Vulkan或其他渲染后端

#### 2.6.2 裸数组参数
- **严重程度**: 低
- **位置**: `dolas_rhi.h:59`
- **问题**:
  ```cpp
  void ClearRenderTargetView(std::shared_ptr<RenderTargetView> rtv, const Float clear_color[4]);
  ```
- **建议**: 使用 `std::array<Float, 4>` 或 `Vector4`

#### 2.6.3 过长的参数列表
- **严重程度**: 低
- **位置**: `dolas_render_primitive.h`
- **问题**: 部分函数参数过多，建议使用结构体封装

### 2.7 类型系统问题

#### 2.7.1 类型转换风险
- **严重程度**: 中等
- **位置**: `dolas_rhi.cpp:226-228`
- **问题**:
  ```cpp
  std::size_t rt_count_sz = d3d11_render_target_view.size();
  if (rt_count_sz > k_max_render_targets) rt_count_sz = k_max_render_targets;
  if (rt_count_sz > (std::size_t)(std::numeric_limits<UINT>::max)()) rt_count_sz = (std::size_t)(std::numeric_limits<UINT>::max)();
  ```
- **问题**: 每次调用都进行安全检查，应在断言中处理

### 2.8 构建系统问题

#### 2.8.1 CMake环境依赖
- **严重程度**: 中等
- **位置**: `CMakeLists.txt:19-21`
- **问题**:
  ```cmake
  include_directories("$ENV{WindowsSdkDir}Include/$ENV{WindowsSDKVersion}/um")
  link_directories("$ENV{WindowsSdkDir}Lib/$ENV{WindowsSDKVersion}/um/x64")
  ```
- **问题**: 依赖环境变量，在不同开发环境中可能失效

## 3. 重构方案

### 3.1 阶段一：修复基础问题（1-2周）

#### 3.1.1 命名修复
- **任务**: 修复 `m_postion` → `m_position`
- **文件**: `dolas_math.h`, `dolas_rhi.cpp`
- **风险**: 低，需要全局搜索替换

#### 3.1.2 常量整理
- **任务**: 移除重复的 `DOLAS_FLOAT_POSITIVE_INFINITY`
- **文件**: `dolas_math.h`
- **建议**: 
  ```cpp
  #define DOLAS_FLOAT_INFINITY (std::numeric_limits<Float>::infinity())
  #define DOLAS_FLOAT_NEGATIVE_INFINITY (-std::numeric_limits<Float>::infinity())
  ```

### 3.2 阶段二：改进内存管理（2-3周）

#### 3.2.1 COM资源智能指针化
- **任务**: 引入 `Microsoft::WRL::ComPtr` 或自定义COM智能指针
- **示例**:
  ```cpp
  // 替换前
  ID3D11Device* m_d3d_device;
  
  // 替换后
  Microsoft::WRL::ComPtr<ID3D11Device> m_d3d_device;
  ```

#### 3.2.2 资源视图模板化
- **任务**: 创建通用的 `D3DResourceWrapper<T>` 模板类
- **优势**: 消除重复代码
- **示例**:
  ```cpp
  template<typename T>
  class D3DResourceWrapper {
  public:
      ~D3DResourceWrapper() { if (m_resource) m_resource->Release(); }
      T* Get() const { return m_resource; }
      T** GetAddressOf() { return &m_resource; }
  private:
      T* m_resource = nullptr;
  };
  ```

### 3.3 阶段三：解耦全局依赖（3-4周）

#### 3.3.1 引入依赖注入
- **任务**: 创建 `ServiceLocator` 或构造函数注入
- **方案**:
  ```cpp
  // 方案A: Service Locator
  class ServiceLocator {
  public:
      static void ProvideTextureManager(ITextureManager* manager);
      static ITextureManager* GetTextureManager();
  };
  
  // 方案B: 构造函数注入（推荐）
  class DolasRHI {
  public:
      DolasRHI(ITextureManager& textureManager, 
               IBufferManager& bufferManager,
               IRenderPrimitiveManager& primitiveManager);
  };
  ```

#### 3.3.2 定义Manager接口
- **任务**: 为所有Manager创建接口类
- **示例**:
  ```cpp
  class ITextureManager {
  public:
      virtual ~ITextureManager() = default;
      virtual Texture* GetTextureByTextureID(TextureID id) = 0;
      virtual TextureID LoadTexture(const std::string& path) = 0;
  };
  ```

### 3.4 阶段四：API改进（2-3周）

#### 3.4.1 隐藏D3D实现
- **任务**: 将D3D相关API标记为internal或移至impl命名空间
- **方案**:
  ```cpp
  namespace detail {
      class D3D11Device {
          friend class DolasRHI;
          ID3D11Device* GetRawDevice();
      };
  }
  ```

#### 3.4.2 统一错误处理
- **任务**: 创建统一的错误码体系
- **建议**:
  ```cpp
  enum class Result {
      Success,
      InvalidArgument,
      OutOfMemory,
      DeviceLost,
      // ...
  };
  
  template<typename T>
  class Expected {
      std::variant<T, Error> value;
  public:
      bool IsSuccess() const;
      T& GetValue();
      Error& GetError();
  };
  ```

### 3.5 阶段五：架构重构（4-6周）

#### 3.5.1 Manager职责拆分
- **任务**: 将Manager拆分为：
  - `ResourceFactory`: 负责创建资源
  - `ResourceCache`: 负责缓存和查找
  - `ResourceManager`: 协调上述两者

#### 3.5.2 引入ECS模式
- **任务**: 逐步将渲染实体管理迁移到ECS架构
- **优势**: 更好的数据局部性，更易扩展

## 4. 详细重构计划

### 4.1 优先级矩阵

| 问题 | 影响 | 复杂度 | 优先级 |
|------|------|--------|--------|
| 拼写错误修复 | 低 | 低 | P0 |
| COM智能指针 | 高 | 中 | P1 |
| 全局依赖解耦 | 高 | 高 | P2 |
| API封装 | 中 | 中 | P2 |
| Manager重构 | 高 | 高 | P3 |
| ECS架构 | 高 | 高 | P4 |

### 4.2 文件清单

#### 4.2.1 需要修改的头文件
- `dolas_math.h` - 拼写修复，常量整理
- `dolas_base.h` - 完善类型别名，添加智能指针支持
- `dolas_rhi.h` - COM智能指针，API封装
- `*_manager.h` - 提取接口，依赖注入

#### 4.2.2 需要修改的源文件
- `dolas_rhi.cpp` - 资源管理重构，错误处理统一
- `dolas_shader.cpp` - 内存管理改进
- 所有 `*_manager.cpp` - 解耦全局依赖

#### 4.2.3 需要新增的文件
- `dolas_com_ptr.h` - COM智能指针封装
- `dolas_result.h` - 错误码系统
- `dolas_service_locator.h` - 服务定位器

## 5. 编码规范更新

### 5.1 新增规范

#### 5.1.1 COM资源管理
```cpp
// 推荐: 使用ComPtr
Microsoft::WRL::ComPtr<ID3D11Device> device;

// 不推荐: 裸指针
ID3D11Device* device;
device->Release();
```

#### 5.1.2 依赖注入
```cpp
// 推荐: 构造函数注入
class Renderer {
public:
    explicit Renderer(ITextureManager& tm) : m_texture_manager(tm) {}
private:
    ITextureManager& m_texture_manager;
};

// 不推荐: 全局依赖
Texture* tex = g_engine.m_texture_manager->GetTexture(id);
```

#### 5.1.3 错误处理
```cpp
// 推荐: 使用Result类型
Result DoSomething() {
    if (failed) return Result::Failure;
    return Result::Success;
}

// 不推荐: 不一致的返回值
bool DoSomething(); // 有时void，有时bool
```

### 5.2 禁用模式

- ❌ 禁止使用 `g_dolas_engine` 直接访问
- ❌ 禁止裸 `new/delete` 管理D3D资源
- ❌ 禁止暴露底层API（如 `GetD3D11Device`）
- ❌ 禁止未经验证的C风格类型转换

## 7. 风险评估

### 7.1 高风险项
1. **COM资源迁移**: 可能影响渲染稳定性
2. **全局依赖解耦**: 改动面广，可能引入bug

### 7.2 风险缓解
- 每个阶段完成后进行完整测试
- 保持功能分支，便于回滚
- 逐步替换而非一次性重写
- 使用静态分析工具检查

## 9. 附录

### 9.1 代码坏味道示例

#### 坏味道1: 重复的析构函数
```cpp
// 现状 - 重复代码
RenderTargetView::~RenderTargetView() {
    if (m_d3d_render_target_view) {
        m_d3d_render_target_view->Release();
        m_d3d_render_target_view = nullptr;
    }
}

DepthStencilView::~DepthStencilView() {
    if (m_d3d_depth_stencil_view) {
        m_d3d_depth_stencil_view->Release();
        m_d3d_depth_stencil_view = nullptr;
    }
}

// 改进后 - 使用模板
class RenderTargetView : public D3DResource<ID3D11RenderTargetView> {};
class DepthStencilView : public D3DResource<ID3D11DepthStencilView> {};
```

#### 坏味道2: 全局依赖
```cpp
// 现状
void SomeFunction() {
    Texture* tex = g_dolas_engine.m_texture_manager->GetTextureByID(id);
}

// 改进后
class SomeClass {
    ITextureManager& m_texture_manager;
public:
    explicit SomeClass(ITextureManager& tm) : m_texture_manager(tm) {}
    
    void SomeFunction() {
        Texture* tex = m_texture_manager.GetTextureByID(id);
    }
};
```
